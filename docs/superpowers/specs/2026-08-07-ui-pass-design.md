# UI-проход по четырём окнам — спека

**Дата:** 7 августа 2026
**Слой:** 2 (UI) — лёгкая спека, TDD на логику, но не на вёрстку
**Статус:** утверждена, превью просмотрено

---

## Зачем

Четыре окна приложения писались в разное время и разошлись. Проход системный:
остаёмся в текущем визуальном языке (VisionOS-стекло, кольцо blue→green,
Inter + JetBrains Mono), правим иерархию, согласованность между окнами, контраст
и «дорого выглядит». Логика таймера не трогается.

Основание — аудит шести независимых линз (панель, ящик настроек, виджет+часы,
дисплей, токены, контраст+a11y) с последующей проверкой каждой находки
скептиком по исходникам: **75 подтверждено из 101, 26 отклонено**.

Отклонения показательны и задают границу прохода:

> «Чистая перепрошивка литералов на токены с теми же значениями — на экране
> не меняется ничего.»

То есть в проход **не входит** приведение литералов к токенам ради порядка.
33 разных значения `rgba(255,255,255,·)` в `control.css` — это не дефект, а
объяснение, почему иерархию сейчас нечем выразить. Лечится введением лестницы
поверхностей **с новыми значениями**, а не переименованием старых.

Так же отклонены как вредные: сведение трёх красных перерасхода (`#ff4444` /
`#ff453a` / `#ff3333` — разница 10 единиц в одном канале, глазом не видна),
выравнивание трекинга цифр панели с остальными окнами (у панели фиксированные
72px, это самый мелкий экземпляр из четырёх — широкий трекинг там уместен) и
сведение трекинга чипов статуса (2px у дисплея — проектор, 0.5px у виджета —
окно 250px).

## Границы

**Входит:** CSS и разметка всех четырёх окон плюс точечные правки JS там, где
без них правка невозможна. Полный список правок JS, чтобы объём не оказался
занижен:

| Файл | Что | Зачем |
| --- | --- | --- |
| `electron-widget.html` | `updateAnalogDisplay` + `initElements` + массив `analogElements` | часовая стрелка: угол, ссылка на элемент, окраска в перерасходе |
| `electron-widget.html` | `applyColors`: снять подстановку цвета по умолчанию, отдать секундную стрелку CSS, убрать альфу у цифр под аналогом | владельцем дефолта становится CSS, как уже сделано в часах |
| `constants.js` | `DEFAULT_TIMER_COLORS` + `Object.freeze` | один владелец дефолта на четыре окна |
| `display-script.js` | ветка `else` в `loadColors`, `#ffc107` → `#ffcc00`, `_baseAnalogDigitalColor`, `custom-bg` в `applyBackground`, удаление мёртвого поля `glyph` | дефолт, мёртвое правило `.warning`, режим «Заливка» |
| `electron-control.html` | `buildThemeGrid` + `highlightActiveThemes`: `role`/`aria-checked`/`aria-label`; `TITLES.display` → «Дисплей» | свотчи как группа радиокнопок; одно имя окна вместо трёх |
| `color-picker.js` | пипетка становится `<button>` с `aria-expanded` и живым классом `active` | правило `.color-picker-toggle.active` в CSS есть и мертво |

Правки идут вместе со своим CSS: разнести их по разным задачам нельзя — часть
CSS-правил без JS остаётся мёртвой, а часть JS-правок без CSS ломает вид.

**Не входит:** декомпозиция `TimerController`, новые функции, изменение
поведения таймера, IPC, схема настроек.

## Шесть причин

Семьдесят пять симптомов сводятся к шести корневым, и правка идёт по причинам,
а не по строкам: одна правка гасит от трёх до десяти симптомов.

### A. В тёмной теме нет ни лестницы поверхностей, ни шкалы заголовков

`--tw-level-1/2/3` объявлены только внутри `[data-theme="light"]`
(`design-tokens.css:143-145`). В тёмной теме все заливки написаны литералами.
Одновременно `.timer-header h1` и `.group-title` совпадают по **всем пяти**
свойствам (`control.css:757-764` и `967-975`), а компактный блок в конце файла
сводит их ещё и к одному кеглю — отсюда «пять одинаковых серых полос».

Правки:

- ступени `--tw-level-1/2/3` вводятся в тёмный блок; полупрозрачные, а не
  сплошные как в светлой — панель лежит на радиальном градиенте
  `.app-shell::before`, сплошная заливка его срезала бы;
- три уровня заголовков: лейбл героя 11px/1.6px/`--tw-fg-muted`, заголовок
  секции 10px/1px/700/`--tw-fg-dim`, подзаголовок внутри карточки — свой класс
  вместо инлайнового `style` в `electron-control.html:570, 583`;
- `border-top: 1px solid var(--tw-divider)` снимается с `.manual-time-row` и
  `.timer-mode-row`: тот же токен разделял и секции, и строки внутри секции.
  **Литерал сюда подставлять нельзя** — в светлой теме `rgba(255,255,255,·)`
  на белом исчезает совсем;
- градиент героя `control.css:749` поднимается с 2% до 7%: 2% белого поверх
  `#1e1e22` даёт +4.5/255, то есть ниже порога 8/255, который инструмент
  сверки самого проекта считает изменением. Правило было, эффекта не было.

### B. Компактный блок в конце `control.css` переопределяет геометрию вслепую

- `.quick-window-btn .qw-icon` (`:3225`) обнуляет **габарит** круглой подложки
  значка, оставляя её фон и `border-radius: 50%` — вместо кружка рисуется
  пятно по размеру глифа, и заливка активного состояния почти не читается;
- геометрия ящика объявлена дважды: правила `:269/287/322` мертвы, живут
  `:3233-3235`. Заодно внутренний отступ тела ящика несимметричен —
  слева 14px, справа 10px;
- левый край панели набран тремя значениями (12/14/16px) в шести правилах:
  заголовок «НАСТРОЙКИ» и полоса вкладок стоят на 2px правее панели, футер —
  на 2px левее. Вводится одна ручка `--panel-inset: 14px` на `.app-shell`;
- заголовок титлбара стоит на 10.5px левее центральной оси: левый кластер
  кнопок 31px, правый принудительно 52px, `space-between` центрирует надпись
  в остатке. Лечится `min-width: 52px` на `.window-controls`.

### C. Цвет пишется инлайном из JS, поэтому CSS-состояния мертвы

- **Отмена неона в светлой теме мертва.** `[data-theme="light"]` и `:root`
  имеют одинаковую специфичность (0,1,0), а общий блок `:root`
  (`design-tokens.css:217`) идёт **ниже** светлого и переобъявляет
  `--tw-shadow-panel` и `--tw-glow-blue/green/red`. Комментарий рядом гласит
  «глубина на светлом даётся тенью, а не свечением» — намерение верное, оно
  просто никогда не работало. Токены живые: `control.css:777, 816`,
  `electron-clock-widget.html:144`.
  Лечится переносом четырёх объявлений из общего блока в блок
  `:root, [data-theme="dark"]`.
  **Осторожно:** `electron-clock-widget.html:142-144` записан как список
  `0 2px 4px rgba(0,0,0,0.5), var(--tw-glow-blue)`, а `none` внутри списка —
  невалидное значение: подстановка сделает объявление invalid at
  computed-value time и снимет `text-shadow` целиком. Поэтому вместе с
  переносом добавляется явное `[data-theme="light"] .time-display { text-shadow: none }`.
- **Три окна — три дефолтных цвета.** Панель `#667eea`/`#764ba2` (фиолетовая
  пара, которой нет в токенах), виджет `#0a84ff`/`#30d158`, дисплей не
  применяет ничего и остаётся на CSS-зелёном. Отсюда «один стиль — разный цвет
  в разных окнах». Вводится `CONFIG.DEFAULT_TIMER_COLORS`, `Object.freeze`,
  три литерала заменяются ссылкой на него.
- `.main-btn.start:disabled`: общее правило даёт `opacity: .4` +
  `grayscale(.6)`, зелёный круг превращается в мутно-оливковый и читается как
  поломка. Заменяется нейтральным «недоступно».
- `.digital-time.warning` мёртв: JS пишет `#ffc107` инлайном, CSS говорит
  `#ffcc00`. Приводится к токену.
- Плашка статуса панели никогда не окрашивается состоянием — цвет несёт одна
  8-пиксельная точка, тогда как полноэкранное окно заливает плашку целиком.
  Добавляются три правила через `:has()` (Chromium 43 поддерживает).
  **Палитра прежняя, анимация плашке не добавляется**: пульсация — единственное,
  что отличает «перерасход» от «завершено».

### D. Светлая тема не доехала до окна часов

Восемь мест, где подложка задана тёмным литералом, а текст берётся из токена:
в светлой теме получается тёмное по тёмному либо белое по белому. Проявляется
на профиле, где цвета часов ни разу не выбирались, — то есть на свежей
установке, потому что `applyColors()` при отсутствии `clockColors` выходит по
`if (!colors) { return; }`.

Правки — блок `[data-theme="light"]` внутри `<style>` самих часов: стрелки,
карточки флипа, шильдики даты и пояса, надстрочные секунды (0.55 → 0.62),
снятие чёрной тени под тёмными цифрами.

**Виджет и полноэкранный дисплей остаются тёмными в обеих темах** — фон этих
окон красит пользователь инлайново, и он тёмный по умолчанию.

### E. На дисплее композиция и кегли зашиты в пиксели

- лейбл «ОСТАЛОСЬ» — обычный ребёнок центрируемой колонки, поэтому смещает
  центр кольца вниз на половину своей высоты. Замер на кадре 1280×720: центр
  кольца 384px при центре окна 360px. Лечится симметричным
  `padding-bottom` у `.display-container`, **не** выносом лейбла в `fixed`;
- лейбл и чип статуса не растут с экраном, тогда как цифры привязаны к
  `--ring-size`: на 4K это самые мелкие элементы кадра. Трекинг переезжает
  в `em`;
- диаметр кольца зажат 800px **трижды** (`min(…, 800px)` плюс дублирующие
  `max-width`/`max-height`). Доли вьюпорта не трогаются: до 2909px кадр
  байт в байт прежний, эталоны сверки не переписываются;
- трек и деления круга вдвое бледнее аналогового циферблата в том же файле на
  тех же ролях и не дотягивают до 3:1;
- `.time-text` — Inter 200, единственный из четырёх стилей окна легче 500.

### F. Состояние передаётся классом, но не деревом доступности

Свотчи цвета → `radiogroup`/`radio`/`aria-checked` (паттерн уже применён рядом,
у сегментированных контролов). Пипетка → настоящая `<button>` с
`aria-expanded`. Мишени по `--tw-hit-min`. Значки групп — inline SVG вместо
эмодзи, всем `aria-hidden`. Полноэкранное окно получает одно имя вместо трёх
(«Дисплей» в ряду окон, «Полноэкр.» на вкладке, «Полноэкранный» в шапке ящика).

## Принятые решения

| Вопрос | Решение | Почему |
| --- | --- | --- |
| Эмодзи в заголовках групп | inline SVG, шесть значков по понятиям | Эмодзи не наследуют `currentColor`, не участвуют в темах, различаются на трёх платформах; в светлой теме ✨ почти невидим на белом |
| Часовая стрелка виджета | добавить (разметка + CSS + 3 строки JS) | Её нет вообще: таймер на 1:30 и на 30 минут показывают одинаковое положение стрелок |
| Три дефолтных цвета | свести к одному | Без этого «один стиль — один вид» недостижим в принципе |
| Флип-часы в светлой теме | тёмная карточка + белые цифры | Два скептика дали взаимоисключающие правки. Выбран вариант с меньшим риском: не трогает градиент, на котором держится анимация переворота, и сохраняет механический вид флипа — у настоящих перекидных часов табло тёмное. Замер: 8.77:1 |
| Минус и плюс в ряду точной настройки | оба нейтральные | Красный означал перерасход. Первая версия красила минусы нейтральным, плюсы синими — превью показало, что это замена одной ложной иерархии на другую. Побочно закрывает находку про контраст плюс-кнопок сразу в обеих темах |
| Мишени кнопок светофора | 24px через прозрачный `::after`, центры остаются в 19px | Исключение по расстоянию (24px между центрами) не выполнено осознанно: у самого macOS 20px. Рисунок не меняется вообще |

## Инварианты, которые проход соблюдает

Перечислены здесь, потому что каждый из них выстрадан и закреплён тестами:

- перерасход всегда красный, оранжевый запрещён;
- палитра статуса: идёт зелёный, пауза оранжевый, завершено красный статичный,
  перерасход красный пульсирующий — **пульсация единственное отличие двух красных**;
- инлайновые цвета сбрасываются пустой строкой, а не `_baseTimerColor`;
- центрируются цифры, а не вся надпись со знаком минус (допуск 1.5px);
- разделитель флипа виджета — точки, `font-size` остаётся 0;
- надстрочные секунды часов: `width: 0; overflow: visible`;
- у виджета и часов окна прозрачные — только `inset`-тени и `border`;
- кольцо в перерасходе невидимо по построению — трек это отдельный элемент
  и он должен быть виден;
- порядок `fonts.css → design-tokens.css → control.css` не меняется;
- `design-tokens.css` содержит токены, а не рецепты;
- внешних URL и сетевых зависимостей не появляется.

## Как проверяется

Проход визуальный, но проверяется замерами, а не взглядом — на глаз в этом
проекте уже дважды ошибались.

1. **Превью до внедрения.** Харнесс берёт настоящий `<body>` окна и настоящий
   CSS, предложения подключает отдельным листом последним. Кадр «до» сверен с
   боевым `screenshots/control-idle.png` — совпал. Харнесс уже поймал три
   ошибки в самой дельте: `background-clip: content-box` рисовал скруглённые
   квадраты вместо кружков светофора; `inset: 6px 0` схлопывал трек
   переключателя до 8px; выросший чип статуса дисплея наезжал на строку
   подсказок (расчёт аудита был сделан по старой высоте плашки).
2. **e2e-замеры** там, где число важнее картинки: центр кольца дисплея,
   угол часовой стрелки виджета на четырёх пресетах, computed `background`
   стрелок часов под `[data-theme="light"]`, ось делений циферблата.
3. **`tests/contrast.test.js`** дополняется новыми токенами; при переносе
   `--tw-glow-*` тест остаётся зелёным — он режет файл по маркерам, общий блок
   в срезы не попадает. Константу `tw-bg-surface` в модели фона инфо-блока
   заменить на `tw-bg-timer`, иначе тест меряет несуществующую подложку.
4. **`npm run visual:baseline` + три подряд `visual:check` по нулям.** Один
   чистый прогон здесь ничего не доказывает.
5. **`npm run ci`** и полный `npx playwright test` на трёх ОС.

## Что перезаписывает эталоны

`control-*` (все), `display-*` круговые и `display-overtime`,
`style-flip-widget-*`, `hours-*-flip-widget`, `style-digital-widget-*`,
`style-analog-widget-*`, `light-*`. Кадры часов в сверке не участвуют — они
показывают живое время.

## Что остаётся незакрытым

- Мишени светофора: 19px между центрами вместо 24px — осознанное отступление.
- Кадры `light-clock-analog` / `light-clock-flip` добавить в съёмку нельзя по
  той же причине, по которой все `clock-*` исключены из сверки; закрывается
  e2e-замером computed-значений.
- Плотность таба «Полноэкранный» приводится к общей сетке частично: карточки,
  строки и заголовки — да, свотчи остаются мельче.
