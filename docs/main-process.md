# Главный процесс: карта модулей

До 25.09.2026 главный процесс был одним файлом `electron-main.js` на 2363
строки. Теперь это точка входа и модули `main-*.js`. Поведение при разбиении
не менялось: те же 45 каналов, те же события `app`, та же досылка окнам.
Сверка — `tests/electron-main-load.test.js` (настоящий главный процесс на
подставке) и e2e.

| Файл | Отвечает за |
|------|-------------|
| `electron-main.js` | Точка входа. Порядок: гард `ELECTRON_RUN_AS_NODE`, гард ключей отладки (SEC-04) — ДО любого локального `require`, журнал, краш-обработчики, ключи Chromium, общее состояние, обвязка IPC (SEC-07), `web-contents-created` (SEC-06), сборка модулей |
| `main-state.js` | ОДИН владелец изменяемого состояния: реестр окон (`windows.controlWindow` …), память ретрансляторов (`relay.lastDisplaySettings` …), `flags.isQuitting`. Объекты запечатаны |
| `main-window-closing.js` | Закрывающееся окно ≠ открытое: `markClosing`, `isUsableWindow`, ОДИН реестр отложенных открытий, `closeDisplayWindow` (выход из полноэкранного по событию + страховка) |
| `main-geometry.js` | `moveWindowBy` / `resizeWindowClamped` / `positionWindowClamped`, отчёт `window-geometry` и по своим событиям окна |
| `main-window-hooks.js` | Что получает каждое окно: `hardenWindow`, запрет масштаба страницы, журнал рендерера, перезагрузка после падения, снимок состояния окон, `announceWindowOpened` |
| `main-windows.js` | Четыре create-функции — единственный владелец «окно открылось» — и уровень окна выше полоски меню |
| `main-timer.js` | Контроллер таймера, настоящий интервал, рассылка `timer-state`, сон машины, каналы `timer-command` / `get-timer-state` / `timer-control` |
| `main-recovery.js` | Снимок восстановления после сбоя: когда писать, когда стирать, запись раз в 10 с |
| `main-event-overrun.js` | Накопитель «47-й этаж»: доклады, журнал, выход и сбой посреди доклада, выгрузка CSV, каналы `event-*` |
| `main-tray.js` | Трей: меню, подсказка, «закрытие панели = скрытие в трей» |
| `main-window-ipc.js` | Каналы окон: открыть / закрыть, список мониторов, перемещение и размер |
| `main-control-ipc.js` | Каналы панели и приложения: размер, ящик, полоса, страница релизов, выход, сброс профиля |
| `main-relay-ipc.js` | Ретрансляторы: цвета, стиль, настройки дисплея и часов, тема, замок, масштаб, блоки, раскладка, пресет, звук |
| `main-lifecycle.js` | Единственный экземпляр, старт (накопитель → восстановление → панель → трей), `before-quit`, `window-all-closed` |

## Правила

- **electron и electron-log требует только точка входа.** Модуль — фабрика
  (`createX(deps)` / `registerXIpc(deps)`), всё внешнее получает параметром.
  Причины две: `electron-main-load` подменяет electron на каждый тест, и
  закэшированный модулем electron был бы чужой подставкой; модуль с настоящим
  electron достал бы настоящий `ipcMain` мимо проверки отправителя.
- **Настоящий `ipcMain` (`rawIpcMain`) не покидает точку входа** — модули
  получают только обвязку `IpcSenders.guardIpcMain`. Точка входа сама каналов
  не регистрирует.
- **Общее состояние — поля объектов из `main-state.js`**, а не копии в
  модулях. Колбэки читают окно из реестра в момент события, как читали глобал.
- **Встречные зависимости** (таймер ↔ трей, панель ↔ трей) передаются
  стрелками, читающими модуль в момент вызова; до конца сборки ни одна не зовётся.
- **Новый модуль** — имя `main-*.js`, строка в `package.json` `build.files`,
  подключение из точки входа. Тесты находят его по шаблону имени.

## Как это проверяется

- `tests/helpers/main-source.js` — `readMainSource()`: точка входа и все
  `main-*.js` одной строкой. Source-level тесты о главном процессе читают его
  ЦЕЛИКОМ, иначе проверка отсутствия была бы зелёной из-за переезда кода.
- `tests/main-modules.test.js` — сироты, `require('electron')` в модулях
  (регулярка и загрузка с ловушкой), `rawIpcMain` вне точки входа, гард SEC-04
  раньше первого локального `require`.
- `scripts/verify-packed.js` — ворота на `app.asar` читают весь главный
  процесс (`readPackedMainSource`), а не одну точку входа.
