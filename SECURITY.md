# Безопасность и приватность

Документ описывает, что приложение делает с системой и данными, и какими
проверками это закреплено. Каждое утверждение здесь либо проверяется тестом из
`tests/` или скриптом из `scripts/`, либо указывает на конкретный файл — чтобы
его можно было перепроверить, а не принимать на слово.

Документ сверен с кодом ветки после 2.9.0 (раздел `[Unreleased]` в
`CHANGELOG.md`): закрытие замечаний приёмо-сдаточных испытаний по Linux-сборке
и аудита безопасности от 25.09.2026.

## Коротко

| Вопрос | Ответ |
|--------|-------|
| Ходит ли в сеть | Нет. Единственный внешний адрес — страница релизов на GitHub; она открывается в браузере пользователя и только по его клику |
| Телеметрия, аналитика | Нет. Собственной нет, служебные обращения Chromium выключены явно |
| Обновляет ли себя само | Нет. Автообновления нет вовсе |
| Нужны ли права администратора | Нет (кроме установки deb-пакета, как у любого пакета) |
| Какие данные хранит | Настройки, загруженные пользователем звуки и фон, итог перелимита мероприятия, снимок таймера для восстановления после сбоя, журнал работы |
| Куда пишет | Каталог данных приложения текущего пользователя; отчёт CSV — только в место, выбранное пользователем в диалоге |
| Открыт ли режим разработчика | Нет. В собранном приложении DevTools окон выключены, а ключи отладки Chromium и Node приводят к выходу |

## Работа без сети

Приложение не обращается в сеть ни при запуске, ни в работе.

- Шрифты поставляются файлами в `fonts/` и подключаются локальными
  `@font-face` (`fonts.css`). Внешних CDN нет.
- Служебные обращения Chromium отключены ключами в `electron-main.js`:
  `disable-component-update` и `disable-features=ChromeVariations,OptimizationHints`.
  Без них движок обращался бы к своим сервисам сам, без единой строки кода
  приложения.
- CSP каждого окна запрещает сетевые запросы из страницы целиком:
  `connect-src 'none'`, внешние источники скриптов, стилей, картинок и звука не
  разрешены (подробнее — «Content Security Policy» ниже).
- Страница релизов (`RELEASES_URL` в `electron-main.js`) открывается через
  `shell.openExternal` по кнопке «Проверить обновления». Адрес — константа в
  главном процессе; канал `open-releases-page` payload не принимает, поэтому
  страница не может попросить открыть произвольный адрес.

Закреплено `tests/release-gates.test.js`: тест падает, если в поставляемом файле
появится адрес `http(s)://` помимо этого, если внешний адрес уйдёт куда-то кроме
`shell.openExternal`, если шрифт начнёт грузиться не из `fonts/`, или если CSP
разрешит внешний источник.

## Обновления

Автообновления нет: `build.publish` равен `null`, зависимостей вида
`electron-updater` в проекте нет. Приложение не проверяет наличие новых версий и
не подменяет собственные файлы. Новая версия устанавливается только обычной
установкой поверх старой.

Проверяется `tests/release-gates.test.js` (включая запрет появления такой
зависимости) и `scripts/verify-packed.js` на собранном `app.asar`.

## Данные и файловая система

Всё ниже лежит в каталоге данных приложения текущего пользователя
(`app.getPath('userData')`; точные пути по ОС — в
[docs/UNINSTALL.md](docs/UNINSTALL.md)).

| Что | Где | Содержимое |
|-----|-----|------------|
| Настройки | `Local Storage/` (localStorage окон) | Цвета, стили, масштабы, позиции окон; загруженные звуки и фон дисплея — `data:`-URL внутри настроек |
| Итог перелимита мероприятия | `event-overrun.json` (`event-overrun-store.js`) | Секунды перелимита, флаг «мероприятие завершено», журнал докладов (время окончания и перелимит, не больше 500 записей). Срока годности нет |
| Снимок для восстановления после сбоя | `last-state.json` (`recovery.js`) | Длительность, остаток, пресет, «идёт ли», время записи. Старше 5 минут отбрасывается; при штатном выходе и в покое стирается |
| Журнал работы | `electron-log`: на macOS `~/Library/Logs/timer-widget/main.log`, на Windows и Linux `<каталог данных>/logs/main.log` | События приложения и консоль окон. Файл до 10 МБ, при переполнении прежний переименовывается в `main.old.log` |

Отчёт о перелимите (CSV) пишется **только** по кнопке «Выгрузить отчёт» и
**только** в файл, который пользователь выбрал в системном диалоге сохранения.

Приложение не читает пользовательские файлы само: звук и изображение
выбираются пользователем в системном диалоге или перетаскиванием в зону сброса
звука панели. Больше ничего с диска не читается.

Кнопка «Сбросить всё» стирает localStorage и кеш
(`session.clearStorageData()` и `clearCache()`). Итог перелимита обнуляет кнопка
«Новое мероприятие» скрытого раздела.

Меры вокруг записи на диск:

- **Атомарная запись** (`atomic-write.js`): `event-overrun.json` и
  `last-state.json` пишутся во временный файл в том же каталоге, `fsync`, затем
  `rename` поверх старого. Сбой посреди записи оставляет прежний файл, а не
  обрезанный JSON. Проверка — `tests/atomic-write.test.js`.
- **Недоверенный вход при чтении**: оба файла при запуске нормализуются —
  битый JSON, чужие типы, отрицательные числа дают чистое состояние, а не
  падение (`tests/event-overrun-store.test.js`, `tests/recovery.test.js`).
- **CSV без формул** (`event-report.js`, CWE-1236): текстовая ячейка,
  начинающаяся с `=`, `+`, `-`, `@`, их полноширинных двойников, табуляции или
  CR, получает апостроф и кавычки — табличный редактор не выполнит её как
  формулу. Числа не трогаются. Проверка — `tests/event-report.test.js`.
- **Журнал без путей**: при выгрузке в журнал пишется только имя файла, ошибка
  записи — только кодом (`ENOENT`, `EACCES`); отвергнутая навигация — схемой и
  последним сегментом пути; отказ IPC — именем канала и причиной, без payload.
  Полный путь содержит имя учётной записи, а журнал уходит в поддержку.
  Проверка — `tests/electron-main-load.test.js` (SEC-11).

Реестр ключей localStorage — `CONFIG.STORAGE_KEYS` в `constants.js`;
`tests/storage-keys.test.js` сверяет его с кодом в обе стороны.

## Изоляция процессов

Все четыре окна создаются с одинаковыми ограничениями:

- `nodeIntegration: false` — в странице нет доступа к Node.js;
- `contextIsolation: true` — код страницы и мост изолированы;
- `sandbox: true` — рендерер работает в песочнице ОС;
- `devTools` включаются только при одновременном выполнении двух условий: запуск
  с ключом `--dev` И приложение не собрано (`!app.isPackaged`).

Проверяется `tests/release-gates.test.js` (перечисляет ВСЕ конструкторы окна и
требует полный набор ограничений от каждого) и `scripts/verify-packed.js` (те же
проверки на упакованном артефакте).

### Ключи отладки в собранном приложении

DevTools окна — не единственный вход. `--remote-debugging-port` и
`--remote-debugging-pipe` открывают протокол отладки самого Chromium, через
который исполняется любой код в любом окне — мимо песочницы, CSP и белого
списка IPC. Поэтому собранное приложение, запущенное с
`--remote-debugging-port`, `--remote-debugging-pipe`, `--inspect` или
`--inspect-brk`, выходит с кодом 1 до создания первого окна и до регистрации
IPC (начало `electron-main.js`). В разработке ключи разрешены: через
`--remote-debugging-port` к приложению подключается Playwright.

Проверка — `tests/electron-main-load.test.js` (SEC-04).

### Фьюзы Electron

Фьюзы — биты внутри бинаря Electron, которые переворачиваются при сборке
(`build.electronFuses` в `package.json`) и не меняются ни ключом, ни
переменной окружения.

| Фьюз | В сборке | Что это даёт |
|------|----------|--------------|
| `RunAsNode` | выключен | `ELECTRON_RUN_AS_NODE` не превращает приложение в интерпретатор Node |
| `EnableNodeOptionsEnvironmentVariable` | выключен | `NODE_OPTIONS` игнорируется |
| `EnableNodeCliInspectArguments` | выключен | `--inspect*` игнорируются |
| `EnableEmbeddedAsarIntegrityValidation` | включён | `app.asar` сверяется с хешем, вшитым при сборке; подменённый архив не запускается |
| `OnlyLoadAppFromAsar` | включён | приложение грузится только из `app.asar`, не из соседнего каталога `app/` |
| `EnableCookieEncryption` | включён | cookie на диске шифруются ключом ОС |
| `LoadBrowserProcessSpecificV8Snapshot` | выключен (как по умолчанию) | — |
| `GrantFileProtocolExtraPrivileges` | **включён (как по умолчанию)** | см. «Известные ограничения» |

`resetAdHocDarwinSignature: true`: сборка macOS не подписана, а перевёрнутые
биты ломают штатную ad-hoc подпись Electron — без её пересоздания arm64 macOS
бинарь убивает.

Биты читаются обратно из собранного бинаря в `scripts/verify-packed.js` (через
`@electron/fuses`) — задание `pack` в CI падает поимённо, если какой-то фьюз не
перевёрнут. Конфиг сторожит `tests/release-gates.test.js`, читалку —
`tests/verify-packed.test.js`.

### Навигация и сброс файлов

- Окно может перейти **только на одну из четырёх своих страниц**
  (`navigation-guard.js`): `will-navigate`, `will-redirect` и
  `will-frame-navigate` на любой другой адрес — включая чужой `file://` —
  отменяются. Адрес сравнивается нормализованным, поэтому `..`, `%2e%2e` и
  двойные слэши не обходят проверку. `window.open` и `<webview>` запрещены
  всегда. Запреты ставятся и в функциях создания окон, и на любой
  `webContents` через `app.on('web-contents-created')`.
- Файл, перетащенный на виджет, часы или дисплей, не открывается вместо окна
  (`drop-guard.js`); у панели свой гаситель (`custom-sounds.js`), который
  пропускает только зону сброса звука.

Без этого HTML-файл, перетащенный на виджет, становился страницей окна — с
мостом IPC и правом `file://` читать диск. Проверки —
`tests/navigation-guard.test.js`, `tests/drop-guard.test.js`.

### Content Security Policy

Политика четырёх окон собирается из одного шаблона в `scripts/csp-hash.js` и
лежит в `<meta http-equiv="Content-Security-Policy">` каждого HTML:

- `script-src 'self'` плюс `sha256` **каждого** инлайнового `<script>` —
  `'unsafe-inline'` для скриптов нет, внедрённый в страницу скрипт не
  исполнится;
- `connect-src`, `object-src`, `base-uri`, `form-action`, `frame-src`,
  `worker-src` — `'none'`;
- `img-src`, `media-src`, `font-src` — `'self' data:` (фон и звуки
  пользователя живут `data:`-URL);
- `style-src 'self' 'unsafe-inline'` — см. «Известные ограничения».

Хеш — отпечаток текста блока, поэтому правка инлайнового скрипта требует
`npm run csp:hash -- --write`; `tests/csp-hash.test.js` падает, если хеш
разошёлся с текстом, и называет команду.

### IPC

Обмен между страницей и главным процессом идёт через `preload.js` с **белым
списком** каналов (`channel-validator.js`), раздельным для отправки и приёма.
Канала «на всё» нет; неизвестный канал отбрасывается. Мост не даёт `invoke`.

Белый список отвечает на вопрос «есть ли такой канал», но не «чей он». Поэтому
главный процесс проверяет **отправителя** каждого сообщения
(`ipc-senders.js`): одна таблица «канал → окна, которым его разрешено слать»,
и каждый обработчик регистрируется через обёртку, которая перед вызовом
проверяет, что сообщение пришло из главного кадра одного из четырёх окон, что
адрес кадра — своя страница и что это окно есть в строке канала. Необратимое
(`reset-and-relaunch`, `quit-app`, `event-reset`, `event-finish`,
`event-export`) разрешено только панели. Канал без строки в таблице роняет
загрузку главного процесса — забытое разрешение видно на первом же прогоне
тестов.

Каналы-ретрансляторы (цвета окон, стиль виджета, настройки дисплея и часов)
запоминают payload и досылают его каждому открывающемуся окну, поэтому payload
проверяется до запоминания (`relay-payload.js`): только плоский объект
примитивов, не больше 200 ключей, `__proto__`/`constructor`/`prototype` не
присваиваются, потолок размера — 64 КБ, у настроек дисплея — под фон 10 МБ в
base64. Сверх потолка payload отвергается целиком, а не обрезается.

Числовые параметры команд таймера, размера, позиции и прозрачности
проверяются на конечность и границы (таймер — целые секунды до 99:59:59).

Проверки — `tests/channel-validator.test.js`, `tests/ipc-senders.test.js`,
`tests/relay-payload.test.js`, `tests/ipc-liveness.test.js`,
`tests/electron-main-load.test.js`.

### electron-log

`log.initialize({ preload: false })`: без этого electron-log добавляет в каждую
сессию второй preload с `window.__electronLog` и собственным каналом в обход
белого списка. Консоль окон попадает в журнал через событие `console-message`
главного процесса. Проверка — `tests/electron-main-load.test.js` (SEC-05).

## Проверка входных данных

- Изображения: ограничение размера (10 МБ), проверка MIME-типа и **сигнатуры
  файла** (для WebP — `RIFF`/`WEBP`). SVG исключён намеренно: это вектор
  исполнения скрипта.
- Аудио: ограничение 5 МБ, MIME и сигнатура; файл с пустым типом отклоняется;
  в `Audio` попадает только `data:audio/`.
- Значения цветов проверяются одним валидатором (`isSafeColor`) перед
  подстановкой в CSS. Пользовательский текст экранируется (`escapeHTML`).
- Ручной ввод времени разбирается строго (`parseManualTime`): всё, что не
  совпало с форматом, отвергается, а не складывается из обрывков.

См. `security.js`, `utils.js` и тесты `tests/security.test.js`,
`tests/security-extended.test.js`, `tests/color-validation-single-owner.test.js`,
`tests/time-utils.test.js`.

## Песочница в Linux

Для Linux поставляется **только deb**. Ключа `--no-sandbox` нет ни в одной цели
сборки: песочница Chromium либо работает, либо приложение не стартует. AppImage
снят с поставки: шага установки у него нет, поднять песочницу там нечем, кроме
этого ключа, — и именно Linux-сборка с ним не прошла приёмо-сдаточные испытания.

Песочнице нужен один из двух механизмов. Скрипт установки deb
(`build/linux-after-install.sh`) выбирает так:

- **user namespaces** — основной путь. С Ubuntu 24.04 AppArmor ограничивает их
  для приложений без профиля, поэтому пакет ставит профиль с `userns,` в
  `/etc/apparmor.d/` (только если местный AppArmor этот профиль понимает);
- **SUID-root на `chrome-sandbox`** (`chmod 4755`, владелец root) — только там,
  где user namespaces в ядре недоступны вовсе. В остальных случаях помощник
  остаётся `0755`: лишний SUID-бинарник — сам по себе поверхность атаки.

При удалении пакета профиль AppArmor выгружается и удаляется
(`build/linux-post-remove.sh`).

Проверяется `tests/release-gates.test.js` и, на собранном пакете,
`scripts/verify-linux-sandbox.js` — в CI и в релизе, на том самом deb, что
уходит пользователям.

## Как проверить самостоятельно

```sh
npm audit                      # уязвимости зависимостей (весь граф)
npm audit --omit=dev           # то, что попадает в приложение
npm run ci                     # lint + unit-тесты, включая release-gates
npm run csp:hash               # CSP окон совпадает с инлайновыми скриптами

npx electron-builder --dir     # собрать без установщика
node scripts/verify-packed.js  # содержимое app.asar, релизные гейты, фьюзы

# фьюзы собранного бинаря (путь зависит от ОС и архитектуры):
npx @electron/fuses read --app dist/mac-arm64/TimerWidget.app
npx @electron/fuses read --app dist/win-unpacked/TimerWidget.exe

# Linux, на машине с dpkg-deb:
npx electron-builder --linux deb
node scripts/verify-linux-sandbox.js
```

## Известные ограничения

1. **Сборки не подписаны.** Сертификата разработчика у проекта нет:
   `mac.identity` равен `null`, подпись Windows отключена. На macOS скачанное
   приложение запускается только после явного разрешения в «Конфиденциальность
   и безопасность»; на Windows SmartScreen предупреждает о неизвестном
   издателе. Подлинность файла проверяется по `SHA256SUMS.txt` рядом с
   загрузками. Когда сертификаты появятся, подпись включается настройками
   сборки без изменений в коде.
2. **`GrantFileProtocolExtraPrivileges` включён.** Окна грузятся с `file://`, и
   с выключенным фьюзом их источник становится непрозрачным: `localStorage`
   бросает «Access is denied for this document», панель падает на старте
   (замерено 25.09.2026 на копии Electron с выключенным фьюзом). Выключить его
   можно только вместе с переездом окон на собственную схему (`app://` через
   `protocol.handle`) — это меняет источник хранилища и требует миграции
   настроек. Риск частично закрыт: навигация ограничена четырьмя своими
   страницами, `connect-src 'none'` запрещает странице `fetch`/XHR.
3. **`style-src 'unsafe-inline'`.** Стили инлайновые повсюду (`style=""`,
   `<style>`); CSS кода не исполняет, скрипты под хешами. Внедрённый стиль
   может исказить вид окна, но не выполнить код.
4. **Девятый фьюз провода неизвестен `@electron/fuses` 1.8.0.** Провод Electron
   44 содержит бит с индексом 8, которому в библиотеке нет имени:
   `npx @electron/fuses read` печатает его как `undefined is Enabled`. Сборка
   его не трогает — он остаётся в значении Electron по умолчанию, и
   `verify-packed.js` его не проверяет.
5. **Ручная проверка установщика Windows** (вопрос об удалении настроек при
   деинсталляции) не автоматизирована.

## Как сообщить об уязвимости

Через приватный отчёт о уязвимости в разделе Security репозитория на GitHub
(вкладка Security → Report a vulnerability). Пожалуйста, не открывайте публичную
задачу до исправления.

Что помогает разобраться быстрее: версия приложения, операционная система, шаги
воспроизведения, ожидаемое и фактическое поведение. Журнал приложения
